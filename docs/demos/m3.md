# Milestone 3 demo — the text engine

What exists: writing and editing a PDF's own text, in English and Arabic, laid out and drawn by our own
engine.

- **Add text:** typed into the page's content, not as an annotation. It prints, copies and searches as
  the page's own.
- **Edit a paragraph in place:**
  - it reflows inside its box, and a single line grows along its line;
  - it keeps its first baseline, alignment and direction.
- **Fonts, in this order:**
  1. the paragraph's own fonts as they are;
  2. their embedded programs, laid out again (Arabic from Chrome's subsets included);
  3. the closest bundled face, chosen by name and widths, with a notice.
- **Styles:** bold, italic, sizes and colours inside a paragraph survive editing; **Bold** and
  **Italic** commands work while editing.
- **Tashkeel:** read in place and removed with its paragraph.
- **Refusals:** text that cannot be edited safely says why, in either language:
  - needs OCR;
  - an unreadable font;
  - rotated;
  - encrypted;
  - shared with other text.

Not yet: underline, sizes and colours from the editor; Type 1 and bare CFF fonts; installed fonts.
See `PROGRESS.md`.

Setup once: `scripts/dev-setup.sh`, `(cd apps/desktop && pnpm install)`, `node fixtures/generate.mjs`.
On this Mac, first: `export PATH=/opt/homebrew/opt/rustup/bin:$PATH`.

Work on copies, so the fixtures stay as they are:

```bash
mkdir -p /tmp/m3 && cp fixtures/out/coretext/en-paragraphs.pdf fixtures/out/chrome/ar-sans.pdf fixtures/out/chrome/ar-vocalized.pdf /tmp/m3/
```

## 1. Fix a typo in English (2 minutes)

```bash
cd apps/desktop && MIRSAM_OPEN=/tmp/m3/en-paragraphs.pdf pnpm tauri dev
```

1. Choose the **Edit** tool, then press on the last paragraph ("Questions? Email…"). The editor
   opens with the paragraph's text. Under it, a note says it is set in the paragraph's own font.
2. Change "call" to "phone" and press `⌘Enter`.
   - The page repaints in place.
   - Every other line is where it was, and nothing new is embedded: the paragraph's own font
     draws it.
3. `⌘S`, then open the saved file in Chrome, Preview and Acrobat Reader. The page is the same
   everywhere, with "phone".

## 2. Insert a word into Arabic (2 minutes)

```bash
cd apps/desktop && MIRSAM_OPEN=/tmp/m3/ar-sans.pdf pnpm tauri dev
```

1. **Edit** tool → press on the last paragraph ("يُرجى من جميع الموظفين…"). Type "والمتعاقدين"
   after "الموظفين" and press `⌘Enter`.
2. What to see:
   - the letters join;
   - the paragraph re-wraps right to left, its right edge and first line where they were;
   - the damma stays on its letter.
3. Save, open in Preview and copy the paragraph: the text is in logical order, as typed.
4. Press the heading ("إشعار للموظفين") and remove the second word. It is set again in the PDF's
   own embedded font: no notice, and the same glyphs.

## 3. A mixed sentence, bold and italic (2 minutes)

1. Anywhere on a page, press with the **Edit** tool where there is no text, and type
   `اشتريت 3 أجهزة iPhone 15 Pro بسعر 4,500 ريال.`
2. Press it again: it opens as a paragraph. Change 3 to 5 and 15 to 16. The order stays right.
3. Select "iPhone 16 Pro" in the editor and press **B** (or `⌘B`). Save with `⌘Enter`. The word is
   bold on the page; `⌘Z` in the field undoes the bold before saving.

## 4. Tashkeel and refusals (2 minutes)

```bash
cd apps/desktop && MIRSAM_OPEN=/tmp/m3/ar-vocalized.pdf pnpm tauri dev
```

1. **Edit** → press a vocalised paragraph. Its text reads exactly as printed, marks on their
   letters.
2. Clear it and save (`⌘Enter`): the paragraph and every mark go.
3. Open `fixtures/out/coretext/ar-plain.pdf` and press its Arabic. A notice says it cannot be
   read reliably and needs OCR: nothing is opened that would damage it.

## 5. Both directions (1 minute)

Switch the UI to Arabic (the language button).
- The editor, its font notice, the B and I buttons and the refusal notices are in Arabic and
  mirror.
- Each paragraph's field keeps its own direction.

## The exit test: spec §7's acceptance tests

`cargo test -p mirsam-core --test m3_exit` (and the real-app self-test below). Measured on this Mac,
2026-11-22:

| Acceptance test | Clause | Result |
|---|---|---|
| **1. Typo in English** | surrounding lines keep their positions | ✓ every other paragraph's box and text unchanged, after save and reopen |
| | opens identically in other viewers | ✓ PDFium (Chrome's engine), Poppler and PDFKit (Preview's engine) each draw the saved page identically outside the paragraph, on a Helvetica letter and on CoreText's own font |
| | | **by hand:** Acrobat Reader, which cannot be driven here |
| | | ✓ all three read the fix |
| **2. Word into Arabic** | letters join | ✓ a word of the paragraph set again is drawn as Chrome drew it: width and ink within 5% |
| | re-wraps right to left | ✓ more lines, the same right edge and first line |
| | copy-paste in another viewer | ✓ exact in PDFKit (Preview) and in this app |
| | | **gap:** PDFium (Chrome) and Poppler reverse the letters of Arabic ligatures ("الموظفني" for "الموظفين"), as they do in Chrome's own unedited file; PDFium reverses whole words there ("نيفظوملل") |
| **3. Mixed sentence** | order stays correct | ✓ in this app and PDFKit |
| | | **gap:** PDFium prints "Pro 16 iPhone" and Poppler prints the line in visual order; both do so for any producer's file |
| **4. Round trip** | no drift, no duplicate fonts | ✓ English (page fonts), Arabic (bundled faces) and Chrome's heading (embedded program), edited, saved, reopened and edited again |

**What the gaps are.** Viewers disagree on how a ligature glyph's letters are ordered for copying.
- Labelling ligatures with `/ActualText` fixed some of PDFium's reading.
- It reversed other words entirely.
- Poppler ignored it.

This is owner item 10 in `PROGRESS.md` (which viewers matter most), now measured.

## Checks behind this demo

- **`cargo test --workspace`:**
  - `tests/m3_exit.rs`: the four acceptance tests, against every viewer present;
  - `tests/block_edit.rs`: in-place editing, styles, embedded fonts, tashkeel and refusals;
  - `tests/added_text.rs`, typeset and layout unit tests.
- **`cd apps/desktop && pnpm test`:** the editor, the B and I commands, notices, in English and
  Arabic.
- **The real-app self-test** (English/light and Arabic/dark; macOS, Linux and Windows in CI):
  - text is added, edited in place, made bold with WebKit's own command, read back and undone;
  - typing in the paragraph field takes 17–18 ms a keystroke (median; spec §11: 32 ms). The first
    keystroke of a session took up to 99 ms.

  Run it with `scripts/selftest.sh <pdf> <out> en|ar light|dark`, then
  `node scripts/check-selftest.mjs <out> ltr|rtl`.
- **Budgets:** the scroll and zoom benchmark could not be measured: it ran while another session's OCR
  benchmark and builds held this Mac at a load average of 85, and its frame times are not evidence
  either way. Re-run on an idle machine:

  ```bash
  scripts/scroll-benchmark.sh /tmp/m3-bench debug
  ```

  ```bash
  node scripts/check-scroll-benchmark.mjs /tmp/m3-bench
  ```
