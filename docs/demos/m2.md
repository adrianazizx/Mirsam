# Milestone 2 demo — annotate and organize

What exists: editing that never touches the original until you save, in English and Arabic.

- **Organize pages:** the page organizer; insert, merge, extract and split.
- **Annotate:** markup, sticky notes, text boxes and ink, with undo and redo.
- **Review:** a comments panel with replies and resolve.
- **Save safely:** saving is validated, and closing with unsaved changes asks first.
- **Recover:** autosave brings unsaved changes back after a crash.

Not yet: callouts, choosing colours and sizes, and moving annotations (see `PROGRESS.md`).

Setup once: `scripts/dev-setup.sh`, `(cd apps/desktop && pnpm install)`, `node fixtures/generate.mjs`.
On this Mac, first: `export PATH=/opt/homebrew/opt/rustup/bin:$PATH`.

Work on copies, so the fixtures stay as they are:

```bash
mkdir -p /tmp/m2 && cp fixtures/out/derived/rtl-book.pdf fixtures/out/chrome/contract-two-column.pdf fixtures/out/derived/encrypted.pdf /tmp/m2/
```

```bash
cd apps/desktop && SAFHA_OPEN=/tmp/m2/rtl-book.pdf pnpm tauri dev
```

## 1. Organizing pages (3 minutes)

1. Choose the **Pages** tool in the rail: the organizer shows the book's four pages (right to
   left in the Arabic UI). Click, Shift-click and `⌘`-click to select; drag to reorder, or use
   **Move pages earlier / later** from the palette (`⌘K`).
2. With a page selected: rotate, duplicate, delete, insert a blank page. Each is one step of
   `⌘Z` / `⇧⌘Z`. The tab shows a dot while there are unsaved changes.
3. **Insert pages from a file…** → pick `contract-two-column.pdf`. Its pages land after the
   selection, selected. Do it again with `encrypted.pdf`: the page area asks for its password
   (a wrong one says so; `safha-test` inserts it).
4. **Extract pages to a new file…** writes the selection as a new PDF; a notice names it.
5. **Split into files…** offers three ways:
   - **By page count:** files of N pages.
   - **At top-level bookmarks:** one file per entry, named after it, and the dialog lists the
     titles. None of the generated fixtures has top-level bookmarks on different pages, so the
     option is disabled for them; any book-length PDF with chapters shows it.
   - **By file size:** each file holds as many pages as fit.

## 2. Annotating (4 minutes)

```bash
cd apps/desktop && SAFHA_OPEN=/tmp/m2/contract-two-column.pdf pnpm tauri dev
```

1. Select a line of Arabic text: the floating toolbar offers **Highlight, Underline,
   Strikethrough, Squiggly**. The page repaints in place, without a flash. Click the markup to
   select it; `⌫` deletes it.
2. Choose the **Comment** tool. **Add note**: click on the page and type in Arabic. The field
   follows the text's own direction. Click the icon again to edit it.
3. **Add text box**: click, type `تمت المراجعة — approved`. The box is drawn with embedded fonts,
   shaped and in the right order. It reads back exactly in other viewers, and when flattened.
4. **Draw** with a pen or a trackpad: pressure widens the line. **Erase ink** removes whole
   strokes.
5. `⌘Z` steps back through all of it; `⇧⌘Z` forward.

## 3. Reviewing (3 minutes)

1. Open the side panel (`F4`), then the **Comments** view (the speech bubble).
2. At the bottom, set **Your name on comments**, for example `مراجِع`. Comments added from now on
   carry it; with no name set, none is written.
3. Each comment shows its author, date and type. Highlights quote the text they mark.
   - **Reply**: type and send (`⌘Enter`).
   - **Resolve** marks it resolved; **Reopen** undoes that.
   - Click a comment to jump to it on its page.
4. Filter by **Open / Resolved**, type, or author. Order by page, latest activity, or author.
5. Replies and states are standard PDF annotations: other viewers show the same thread. They
   draw nothing on the page.

## 4. Saving (2 minutes)

1. `⌘S` saves over the file:
   - written to a temporary file;
   - reopened to validate;
   - renamed into place.

   A signed file is saved incrementally, so its signatures stay valid.
2. `⇧⌘S` saves elsewhere; the tab takes the new name.
3. Make a change and close the tab (`⌘W`), the window, or quit: the app asks first.
   **Don't save** discards.

## 5. Crash recovery (2 minutes)

1. Make a change, wait 2 seconds, then kill the app:

   ```bash
   pkill -9 -f target/debug/safha-desktop
   ```

2. Launch again. **Recover unsaved changes?** lists the document with the time of its last
   change.
   - **Restore** reopens it with the changes. `⌘Z` goes back to the file as it is on disk.
   - **Discard** deletes the recovery copy.
   - **Decide later** asks again at the next start.
3. If the original changed on disk meanwhile, the dialog says so. Saving then asks for a new
   file name.
4. Encrypted documents stay encrypted in their recovery copy, and restoring asks for the
   password again.

## 6. Both directions (1 minute)

Switch the UI to Arabic (the language button). The rail, side panel, comments, dialogs, and
organizer mirror. Arabic and English inside comments keep their own direction.

## Checks behind this demo

- **`cargo test --workspace`:**
  - every edit is reopened by PDFium and checked with `qpdf --check`;
  - markup, notes, text boxes and ink are rendered and compared pixel by pixel;
  - text boxes are flattened and read back in logical order;
  - encrypted files are tested with RC4, AES-128 and AES-256;
  - comment threads, split by bookmarks and size, autosave and recovery are covered.
- **`cd apps/desktop && pnpm test`:** the commands, dialogs and panels, in English and Arabic.
- **The real-app self-test** (English/light and Arabic/dark, on macOS, Linux and Windows in CI):
  - highlights, a note, a text box and a stroke are painted and undone;
  - the comments panel lists them, and a reply and a resolve read back;
  - a page edit is undone;
  - a recovery file is kept, then removed.

  Run it with `scripts/selftest.sh <pdf> <out> en|ar light|dark`, then
  `node scripts/check-selftest.mjs <out> ltr|rtl`.
- **Budgets** (`PROGRESS.md`, M2): scrolling, jumps, search and memory are unchanged from M1.
