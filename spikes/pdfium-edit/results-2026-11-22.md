## Variants

- `a1-settext`: FPDFText_LoadFont(cid) + FPDFText_SetText(logical string)
- `a2-charcodes`: FPDFText_LoadFont(cid) + FPDFText_SetCharcodes(shaped glyph IDs), no positions
- `a3-positions`: A2 + FPDFText_SetPositions (x) + one text object per y offset
- `a4-cid2`: FPDFText_LoadCidType2Font(our subset, our ToUnicode, CIDToGIDMap) + positions as A3
- `a4-cid2-at`: A4 + /Span /ActualText per base+marks group (FPDFPageObjMark_SetBlobParam, UTF-16BE)
- `a4-cid2-at8`: A4 + the same spans via FPDFPageObjMark_SetStringParam (UTF-8 with BOM)
- `a4-safe`: a4-cid2 through pdfium-render's safe wrappers only (load_cid_type2_from_bytes, set_charcodes, set_positions)
- `b-src`: own writer: TJ numbers + Ts for offsets, ToUnicode only
- `b-src-rc`: b-src + /ReversedChars around RTL runs
- `b-src-td`: b-src but Td before every repositioned glyph (Skia style)
- `b-src-cluster`: b-src + /ActualText on clusters ToUnicode cannot reproduce
- `b-src-grapheme`: b-src + /ActualText per base+marks group
- `b-src-word`: b-src + /ActualText per word
- `b-src-line`: b-src + one /ActualText span per line
- `b-src-tuned`: b-src + /ActualText bent to PDFium's extractor (pre-reversed ligatures, pre-mirrored brackets): not spec-conformant
- `b-cmap`: own writer, ToUnicode from the font's cmap where the glyph is encoded (PDFium/Skia convention)
